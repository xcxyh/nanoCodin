- 审查基线：`f0351bc`，2026-10-25。
- 实施状态：运行代码与回归已落地，远端验证以最终提交报告为准；真实模型验收首轮未闭环，用户已要求停止追加付费验收。不发布。

## 1. 判断与证据

当前缺口集中在模型请求、终态协议、工具事实、上下文和长任务验收。需要按契约集中修复，不能用增加等待时间或增加测试数量代替完整任务验收。

真实失败会话：`mvnhl3sa-79e2be0f`。任务历时约 486 秒；第 10 轮生成 21,214 字符的已有文件改写稿，被 create 的 EEXIST 正确阻止；第 17 轮起该错误被裁出模型上下文；第 19 轮在 120.010 秒时被客户端硬截止。没有成功写入目标文件，但会话出现 changed=true。

原始会话只留在本地，不提交私人对话、配置或密钥。下表中的新增问题已用本地小用例验证；没有调用付费模型。

其他静态风险：编辑直接 readFile/writeFile，未提供版本冲突保护；错误记录缺少实际 HTTP 尝试次数、响应进展和可恢复原因；会话读取将不存在、损坏和权限错误都折叠成 null。需要随对应模块修复或验证，不把它们全部归因于这次超时。

## 2. 保留的架构和兼容约束

1. 通用执行循环仍只负责请求模型、校验动作、顺序执行工具、记录事实和结束；不识别任务阶段或按工具名调度。
2. 传输错误分类、请求预算、有限重试和协议差异放在模型适配器；不恢复 RecoveryEngine，不暗改参数，不重跑写工具。
3. 修改与命令依据由工具提供；默认 coding 验证通过可替换 hook 接入。UI 从事实派生，不另存计划、改动或验收副本。
4. 保留 create 只创建新文件、唯一匹配编辑、Handlebars 可选适配器、可编辑 .hbs 和现有终端交互。
5. 不引入 Graph、阶段门禁、委派、索引、向量记忆、自动长期记忆或新运行框架。
6. 现有 model/tools/instructions/ask/save 注入方式继续可用。新字段尽量可选，保留 ToolResult.ok/output、RunStatus 和 --print 的 stdout 契约。
7. 文件路径安全策略与操作系统隔离能力明确分开，不承诺用命令正则实现系统沙箱。

## 3. 第一批：请求、终态与授权

### 3.1 请求预算和错误分类

在内置适配器增加独立的模型请求配置，不复用 sandbox.timeoutMs：

- requestTimeoutMs：一次逻辑请求的总预算，包含网络重试和兼容回退。
- idleTimeoutMs：连续没有收到响应数据的预算；真实响应字节或合法保活可以重置，不重置总预算。
- maxRetries：传输层最多重试次数；建议初始上限为 1 次，禁用 SDK 与外层重复叠加重试。

总预算 10 分钟、无数据预算 2 分钟可作为初始候选，必须通过慢响应和受控真实任务验证后确定。不能只把 120 秒换成更大的硬编码。

配置按 CLI > env > YAML > 默认值解析，SDK 参数保持可选。支持打印生效值，越界或格式错误明确报错。不要改写用户已有配置。

结构化错误至少包含：kind、retryable、provider、HTTP status、实际 attempts、durationMs、可用的服务端 request ID。kind 区分 timeout、cancelled、auth、rate_limit、network、provider、protocol；保留 cause，不把所有错误都提示成检查密钥。

只对适合重试的连接错误、429 和部分 5xx 做有限退避，遵守 Retry-After 和剩余总预算。超时重试要有明确策略和次数，不无条件循环；用户取消立即停止。模型请求重试与工具重放严格分离。

成功或失败都能核对 round 和 attempt。记录首个响应时间、收到的字节数、最后响应时间等必要摘要；不据此猜测服务端正在思考，也不持久化逐字节日志、密钥或完整请求副本。

### 3.2 终态协议

- 统一 final schema，结构化调用、文本回退和自定义模型调用使用相同校验。
- 不接受字符串布尔值、空答案等非法 final；协议错误明确反馈，不伪装完成。
- content-filter 等已知阻塞结果不能落为 complete；长度截断、缺失工具调用、非法参数分别处理。
- 在 beforeFinish 等异步边界返回后、提交 finish 前重新检查取消信号。明确终态提交点，避免取消与成功竞争。
- 对可扩展 hook 补充可选 signal 参数与契约。不能通过 Promise.race 放任未完成的保存或写操作在后台覆盖新结果。
- 审批只有 once/session 两个已知允许值能放行；deny、空值和未知值均不得执行。
- SDK 工具字典使用无原型容器或安全构造，模型可见 schema 与实际可执行工具逐项一致。

## 4. 第二批：编辑能力、工具结果和验证事实

### 4.1 明确区分三件事

- 可能写入：用于权限与中断后的保守判断。
- 确认改动：工具已成功产生明确变化。
- 副作用不确定：执行开始后异常或中断，无法确认实际结果。

保留现有字段兼容，补充可选机器错误码及 uncertainChanges 一类事实。Tool.mutates 表示能力/意图，不能等同于已经修改。已知前置失败如 EEXIST、无匹配、版本冲突返回 no-change，不使旧验证失效。

安全审批的保守规则不能直接写成 changed=true。重点修正实际会话中的只读重定向与搜索字符串误判；对于任意 shell 脚本，准确说明依赖 purpose 声明及可观察事实，未知就保留不确定性，不宣称能完整推断所有副作用。

验证只接受最新已记录改动后的真实检查依据。实际写入和不确定写入都需重新验收；历史不确定操作保留在 review，不能静默清成无改动。外部程序的并发修改不属于纯事件计数能证明的范围。

### 4.2 受保护的整文件改写

推荐在现有 str_replace 中增加显式 rewrite 模式，保持默认工具清单和原有精确替换参数兼容：

- 默认模式继续要求唯一的 oldText 匹配。
- rewrite 模式明确要求 path、newText、expectedHash；不接受缺少版本校验的覆盖。
- view 返回读到的文件版本标识，模型无需把整份旧文件再复制一次作为参数。
- 写前校验版本；检测冲突时失败并要求重读，不暗中合并或改参数。
- 使用同目录临时文件和原子替换，保留权限，明确编码、换行及符号链接策略；不能保证的情况显式拒绝。
- expectedHash 降低读取后生成期间的陈旧覆盖风险；原子替换并不等于对不合作的并发写者提供严格 CAS，不能过度承诺。
- create 的 EEXIST 反馈应给出正确编辑路径和错误码，但仍拒绝覆盖。

新增模式需要用真实兼容 HTTP 测试核对其 JSON schema，不能只验证本地 Zod。重复失败后保留具体错误与纠正方向，不增加按工具名计数的隐藏恢复器。

### 4.3 读取和搜索边界

- view 限制文件类型、读取字节和输出字节，支持取消；按实际显示范围提供续读信息。
- 明确处理超长单行、二进制、设备/FIFO 和越界范围；不把输出截断误当成读完整文件。
- grep 在收集候选时过滤扩展名，分别限制目录遍历与文件数量。
- 搜索受限时输出覆盖范围及截断原因，不能让部分搜索看起来像全仓库不存在。

## 5. 第三批：上下文与模型协议

### 5.1 保留必要纠错依据

- 对每个历史条目先做字段级限额，再进行全局预算分配。
- 参数保留工具名、路径、范围、版本和短摘要；长 content/newText 不应占掉整段历史。
- 为最近结果、未解决失败、未决写操作和当前任务保留空间；不因一个条目稍大就丢弃所有更早依据。
- 失败事实仍由事件推导，保持有界，不建立第二份 working memory 或自动长期摘要。
- 首先用真实会话事件骨架回放：第 17、18、19 轮应仍能看到 create 已失败及可用纠正路径。

可以提示持续没有产生有效变更或反复读取，但不设置“读取几次必须编辑”这类任务门禁，也不把合法的多文件排查当成循环。

### 5.2 原生结构化消息与文本回退分开

支持工具协议的适配器应使用正确的 user/assistant/tool 消息和配对标识，按事件顺序重建上下文。保持批量工具调用顺序，恢复时对未结束调用提供明确的中断结果/说明，不能生成不合法的原生消息序列或自动执行旧调用。

文本回退保留独立、有边界的 action 协议，只在确认能力不支持时使用。认证、限流、网络和 schema 错误不能被误认为端点不支持工具。新增消息元信息保持可选，自定义 Model 的既有实现继续可用。

此项先做本地请求体与会话往返测试，再做有限真实任务对照；不能预先承诺它必然消除所有重复读取。

## 6. 第四批：配置、恢复和兼容收尾

- 统一 CLI 与 SDK 的模型默认值解析；切换 provider 时不隐式沿用另一 provider 的默认模型、地址或密钥。
- 按 skill 名称契约精确匹配，支持已显示在菜单中的合法中文与命名空间名字，非法名字明确提示。
- 工作区身份统一使用规范路径；存储目录定位与会话归属校验使用同一规则。
- 会话读取区分不存在、损坏、版本不兼容和权限错误，保留原文件；新错误元信息与事件升级有兼容测试。
- 明确 Node 最低运行版本并与运行依赖要求对齐；最低版本运行打包消费者检查，完整开发测试使用项目选定的开发版本。
- 保持现有交互：运行中可看事实、模型等待和有界命令输出，结束后自动收起，Ctrl+O 按需查看；不输出原始思考文本。
- 发布流程必须执行完整验证与打包检查后才能 publish。当前不发布；仓库外部自动部署与 npm 发布分开记录。

## 7. 验收矩阵

每批都带对应回归，不把测试留到最后。现有通过的回归继续保留。

| 场景 | 必须核对的结果 |
| --- | --- |
| 长响应、有保活、无数据、断流 | 正确区分 idle/total 超时；提示与实际预算一致；完整响应前不执行工具 |
| 429、503、401、用户取消 | 次数有上限、取消不中途重试、认证错误不重试、无双层重试叠加 |
| hook 等待中取消、取消与 final 竞争 | 终态唯一，取消后不能再开始写工具或提交虚假的 complete |
| 无效审批值 | 命令不执行，记录拒绝或交互错误 |
| final 参数错误、content-filter、截断、混合批次 | 不报成功；各路径与结构化 schema 一致 |
| 已有文件重写、hash 冲突、写入中断 | create 不覆盖；显式改写成功；冲突保留外部修改；不确定写入可恢复核对 |
| EEXIST、无匹配、只读重定向、搜索 npm install | 改动事实准确，不误伤验证状态 |
| 大输入、多轮读取、错误后的纠正 | 必要错误仍在上下文内；参数和结果都有界；历史顺序正确 |
| 大文件、长行、过滤后搜索、取消读取 | 内存/输出受限，续读信息准确，不误报全仓库不存在 |
| 新旧会话、符号链接路径、中文 skill、损坏会话 | 身份一致、能力一致、失败原因清楚，旧文件不被破坏 |
| CLI、SDK、打包消费者、Linux/macOS | 类型、入口、默认工具和输出契约一致；--print 的 stdout 保持最终答复 |

测试分三层：

1. 单元与 fake clock：分类、预算、schema、投影、裁剪和错误事实。
2. 本地兼容 HTTP + 真实工具/CLI/跨进程恢复：慢响应和错误序列受控，不调用付费 API；用同步屏障代替短时钟猜测。
3. 受控真实模型任务：在临时项目副本完成“读取已有 landing page → 显式编辑 → 构建 → 核对产物”；预先明确模型、费用和停止条件。视觉质量用预览或人工核对，不把构建成功等同于设计验收。

覆盖率扩大到模型适配器、文件/shell 工具、存储、验证规则和 UI；按实际覆盖报告设置基线。测试数量和总覆盖率不能代替上述场景。

## 8. 实施与交付顺序

1. 请求与终态/授权：优先修超时、错误分类、取消、final 和无效审批。
2. 编辑与事实：安全改写入口、明确错误、副作用三态、读取边界及验证失效规则。
3. 上下文与协议：修真实错误被裁掉的问题，再接原生消息；做任务对照。
4. 配置/恢复/兼容收尾，补齐 CI 与发布门槛。
5. 完成一次受控端到端任务验收后，形成可核对交付；是否发布继续由用户明确决定。

每批为独立可审查提交，带 typecheck、测试、build、test:package 及对应 CI。第一至三批是同一个可靠性里程碑，不能只改大超时后宣称整条工作流已修复。

不丢弃这次失败会话及其生成稿，不自动将失败的生成内容写入当前工作区。实施证据与剩余限制见 `docs/RELIABILITY_ACCEPTANCE.md`。不得把本地/CI 通过表述成真实模型闭环已经通过。
