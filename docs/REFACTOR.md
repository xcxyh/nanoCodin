# NanoCodin 整体重建方案

> 状态：已按确认的 Harness 主线整体重建并完成本地验收。尚未发布到 npm。

## 1. 产品边界

NanoCodin 是本地终端里的 coding agent。核心流程只有：接收任务 → 查代码 → 改代码 → 运行检查 → 交付；过程中可取消、追问和续接。

首先保证能完成真实代码任务、核心代码容易读懂。多 Agent、通用自动化平台、长期记忆系统、仓库知识库不属于这一版。

已确认主线：**可定制的极简 Harness**。核心易读、可嵌入，模型、工具、指令、交互和存储都可注入。CLI 是同一个核心的一种使用方式。

恢复、检查结果和 review 属于默认 coding 工作流的基础支持。它们不扩展成独立的任务交接系统，也不写死进通用循环。

特色必须能由使用者操作验证：

- `import { createAgent, defineTool } from "nano-codin"` 即可嵌入。
- 不依赖 API Key、配置文件或 Ink 就能注入自定义模型与工具。
- 修改 `instructions` 调整行为；修改 `beforeFinish` 调整完成条件。
- 使用内置工具集合，或者完全替换；不存在隐藏的默认工具。
- 持久化只是可选 `save(session)` 回调；UI 接收同一套事件。
- 默认工具、模型适配器、项目 skills 和文件会话存储均有独立子入口。

## 2. 现有 feature 的最终处置

| 现有能力 | 结论 | 最终能力与边界 |
| --- | --- | --- |
| ReAct loop / Graph 包装 | 重建 | 一个普通异步循环；不保留 Graph 概念及节点合并机制 |
| discover / plan / execute / verify / finalize | 删除 | UI 可以展示正在做什么，标签不控制工具执行 |
| maxSteps、recursionLimit、phaseLimits | 合并 | 只有一种明确的执行预算；停止要记录未完成原因 |
| Structured tool calling | 保留、重建 | 注册 schema 与模型可见工具一致；多调用全部按序处理 |
| 文本 ReAct fallback | 保留、重建 | 接口不支持时才回退；严格解析 JSON；格式错误可纠正 |
| ls / tree / repo_index_query | 合并 | ls 找文件；不启动预扫描、不维护索引缓存 |
| grep | 保留、重建 | 有范围、输出数量和忽略目录约束；可搜索单文件 |
| view / read_context | 合并 | 显式 path、按行读取；规则由上下文层加载 |
| create | 保留、重建 | 只创建新文件；避免意外覆盖 |
| str_replace / insert | 合并 | 一个明确的编辑工具；默认要求唯一匹配 |
| bash | 保留、重建 | cwd、取消、超时、输出上限、退出码、权限确认 |
| todo | 保留、简化 | 可选短计划，整份替换即可；没有复杂操作别名或门禁 |
| ask_user_question | 保留、简化 | 执行确实缺信息时提问；提问与权限等待都能取消 |
| summarize_changes / 固定 Execution summary | 删除 | 模型简短交付；详细依据只在主动 review 时查看 |
| delegate / 只读子循环 | 删除 | 单 Agent 先做到可靠，避免子任务状态、预算和摘要再叠一层 |
| RecoveryEngine | 删除 | 结果反馈给模型纠正；不暗中改参数、替换验证命令或重跑操作 |
| WorkingMemory / CompressionSnapshot / DurableMemory | 重建 | 不保留三份业务状态；从会话事件生成有限上下文；历史笔记兼容只读 |
| remember / forget | 删除 | 不自动持久化推断；明确项目规则放 AGENTS.md 或 skills |
| session checkpoint | 重建 | 可选存储适配器保存事件；保留完成、未完成、错误、取消状态 |
| AGENTS.md | 保留 | 当前项目的约束；作为规则进入上下文 |
| context.md / memory.md | 合并 | 可选只读项目说明；不再构成独立的状态管理系统 |
| Skills / slash skills | 保留 | 目录发现、显式调用、按需读正文；不增加调度器 |
| YAML / env / CLI flags | 保留、收敛 | 一种配置模型；CLI > env > 用户 YAML > 默认值 |
| 首次配置向导 | 保留 | 只配置模型所需信息 |
| Ink TUI | 保留原有交互形式，适配新核心 | 品牌欢迎区、边框输入、任务面板、权限高亮、加载动画及状态栏；展示从事件派生 |
| 输入编辑 / @ 文件选择 / slash 选择 | 保留并适配 | 保留原有边框输入、@ 文件选择和带描述的 skills 选择；改为工作区明确、每次打开刷新、可取消的 UI 适配层 |
| Token 统计 | 简化保留 | 有真实 usage 则显示；估算必须标明；不成为交付正文 |
| frontend 宣传站 | 独立保留 | 不进入 CLI runtime；后续文案只描述实现了的能力 |
| npm / CI / 发布工作流 | 保留 | TypeScript + ESM，无新运行框架；发布独立于本次重构 |

## 3. 需要补充的能力

### 必须完成

- **单一事实来源**：用户输入、工具开始、工具结果和结束状态构成一个会话事件流；prompt、UI、恢复和 review 从这里读取。
- **明确的工具结果**：区分成功、失败、拒绝、取消、超时；错误必须回到执行循环。
- **当前改动的验收依据**：检查记录关联改动版本；改完再改则旧检查不代表最新状态。仅有输出中的 passed/test 字样不算通过。
- **可嵌入 API**：模型、工具、指令、提问、事件与存储有明确的 TypeScript 接口，提供可运行示例。
- **基础恢复**：保存事实记录，恢复后提供上下文，取消时不自动重放写操作。
- **可核对交付**：默认答复短；主动 review 才查看改动和命令依据。成功不删除执行记录。
- **脚本执行**：无 TUI 的单次执行，最终答复与退出码可被程序消费。
- **真实链路验收**：不只 mock agent；用本地兼容 HTTP 接口及子进程验证 CLI、SDK、工具、会话恢复。

### 本版不做

MCP、插件市场、浏览器控制、远端执行、自动提交发布、多 Agent、后台任务平台、向量检索、自动长期记忆、复杂任务 DSL。

## 4. 新架构

```text
CLI / Ink UI
    ↓ 任务与用户交互
Agent run() ──→ Model adapter
    │              返回工具请求或最终结果
    ├────────→ Tool executor
    │              返回真实执行结果
    └────────→ Session events
                   ↓
             Context / Review / Resume
```

### 模块职责

- **agent**：通用执行循环和有限上下文；完成条件是可选 hook，不负责文件存储或终端渲染。
- **workflows**：默认 coding 验证规则，通过 `beforeFinish` 接入，可替换或省略。
- **model**：OpenAI / Anthropic 接口差异、工具协议与兼容回退；不执行工具。
- **tools**：文件、搜索、shell、计划、提问；不持有整个 Agent 或 Session。
- **session**：一种版本化事件格式、原子落盘、读取与 review；没有独立的 working/durable/compression 状态。
- **config/context**：配置、路径、项目规则和 skill 目录；不推断任务阶段。
- **ui/cli**：提交任务、响应提问、展示事件；不另存 todo、验证、memory 副本。

### 依赖约束

- Agent 通过接口使用 model、tools、session，不依赖 Ink。
- tools 只接收 cwd、sessionId、signal、权限/提问回调，工具配置在构造时传入，不能访问其他工具或调用子 Agent。
- Session 是事实；计划、验证和 UI 状态均为派生结果。
- 一个任务的状态只能由一个执行入口修改。
- 保留 TypeScript、ESM、AI SDK、Ink、Zod；不增加新框架。

## 5. 重建方法

1. 先固定能力边界、数据格式和模块接口。
2. 以新目录和数据模型实现 runtime；不继续在旧 services 体系增加补丁。
3. 接入模型和统一工具执行，再接 UI 和 CLI。
4. 删除旧实现、兼容壳和不再适用的测试；原测试中仍成立的场景迁入新模块。
5. README、宣传站与 CLI help 统一到最终实现。
6. 执行 typecheck、test、coverage、build、打包检查和 CLI 链路测试。

## 6. 验收场景

0. 不启用 CLI、真实模型和内置工具，运行自定义模型 + 自定义工具的嵌入示例。
1. 真实项目完成读 → 改 → 检查 → 简短交付，无强制规划往返。
2. 工具名错误、参数错误、文件不存在、命令不存在都能看到明确结果并纠正。
3. 模型一次返回多个工具请求，按顺序执行且不遗漏；混合 final 的错误批次明确拒绝。
4. 不支持 tool calling 的接口只做一次兼容探测；文本参数有完整 schema。
5. 检查失败、检查后再编辑、验证不可用分别表现为真实状态。
6. 模型请求、命令执行、权限等待、提问等待期间均能取消。
7. 进程退出后恢复原任务，不因丢失记录而重复创建文件或重跑已完成写操作。
8. 完成、失败、取消、预算耗尽的会话均可 review，且没有伪装成成功的 UI 状态。
9. 新任务/新会话不误用旧任务的计划或验收结果；连续追问保留必要上下文。
10. 默认输出没有 Execution summary、空字段、长命令转储和内部状态。

## 7. 已知证据限制

最近一次成功任务的 checkpoint 被旧实现清理，当前目录没有可恢复的完整原始对话；截图能核对固定长摘要问题，其他问题需源码及可复现测试定位。不能声称已重放那次完整会话。

## 8. 旧内部数据边界

旧用户配置中的 model、sandbox、maxSteps 继续生效；被删除的 phaseLimits、recursionLimit、repoIndex、recovery、compression 不再参与执行。旧 CLI 参数会给出弃用提示。

新会话采用 `sessions/<id>.json` 的事件格式；不会伪装恢复旧版本只有摘要的 checkpoint，也不修改旧文件。`--resume` 只读取新格式，旧笔记 context.md / memory.md 继续只读加载。

内置工具名保留核心八项，但 todo 输入改成整份计划，不保留操作名及别名推断。核心循环不判断特定工具名称来推断阶段或权限。

## 9. 本地验收结果（2026-10-25）

- `src` 从 69 个文件、8,009 行，收敛为 38 个文件、2,474 行；通用执行循环文件 144 行（含接口与辅助函数）。
- `typecheck`、CLI build、frontend build、diff 检查通过。
- 80 项自动测试通过；当前 CI 纳入的核心模块行覆盖率 96.71%。移除旧机制专用测试，并迁入仍有效的行为场景。
- 本地 HTTP + 真实 CLI 子进程：未知工具纠正、多工具调用、文本协议回退及跨进程恢复通过。
- 现有真实模型在独立临时项目完成 ls → view → str_replace → bash，修复加法实现；`npm test` 两项检查通过，最终答复简短。
- 真实 PTY：命令审批、Esc 取消等待、/clear 新会话、/quit 退出通过。
- `npm run test:package`：打包后解包为独立消费者，核心与四个适配器导入、CLI help、TypeScript 参数推断通过；核心导入没有加载 Ink、AI SDK 或 execa。该检查已加入 CI。

这些结果验证了上述具体场景，不代表所有模型与真实项目都已覆盖。现有真实模型的小任务只进行一次独立实测。

## 10. 模板与原 UI 的恢复取舍

Handlebars 恢复为 `nano-codin/templates` 可选适配器。CLI 使用 `.hbs`，支持项目、用户及包内默认模板，变量、conditions、loops、helpers 和 partials 可定制。核心入口和通用执行循环均不导入模板引擎。模板每次任务重新读取，纯文本数据不做 HTML 转义。

| 原交互 | 处置 | 接入方式 |
| --- | --- | --- |
| 品牌欢迎区与模型/路径信息 | 保留 | 欢迎时展示；会话中或小终端使用紧凑栏 |
| 带边框的输入区、光标编辑快捷键 | 保留 | 继续使用原输入编辑语义 |
| @ 文件选择与过滤 | 恢复 | 明确 cwd；按需读取 Git 文件列表或有界遍历；每次打开刷新 |
| skills/内置命令菜单 | 恢复 | 保留描述、skill/内置类型、六行滚动高亮及上下选择；选择后插入而非直接运行 |
| 任务面板与进度 | 保留形式 | 计划来自会话事件，不维护 AgentExecutionSnapshot 副本 |
| 权限问答、快捷键、高亮 | 保留 | 注入 ask 回调；等待时仍可取消 |
| 加载提示与动画 | 保留 | 只表示真实运行状态，不输出重复的内部 Thought 字段 |
| 模型/token 底栏 | 保留 | 从会话 usage 派生，保留估算/混合来源标记 |
| 双 Ctrl+C 退出 | 恢复 | 关闭 Ink 默认抢先退出；选择器优先关闭、运行时取消、空闲时二次确认 |
| 旧 reducer、Graph、三层 memory | 不恢复 | UI 只持有输入、选择和问答等交互状态 |

此前将良好 UI 一并删去的取舍已撤销；本节更新优先于上一轮的数量快照。旧版功能专用测试中与这些交互相关的部分已恢复，并加入真实 Ink 输入回归。

本轮验收：118 项测试、typecheck、build、打包消费者检查均通过。核心依赖边界检查新增 Handlebars；模板项目覆盖、HTML 字符保真、修改后重新加载和 helper/partial 隔离均有回归测试。真实 Ink 输入测试覆盖文件选择、skills 滚动、双 Ctrl+C、任务进度、权限回答与取消；真实 PTY 也核对了欢迎布局、带空格路径插入、第八项 skill 选择与命令审批。
